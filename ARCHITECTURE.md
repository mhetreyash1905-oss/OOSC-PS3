# System Architecture & Workflow: Civic Rights Navigator

This document explains exactly how the different technologies in this project connect and work together to turn a plain-language citizen complaint into a fully drafted RTI application.

## 1. The Core Concept: "RAG" (Retrieval-Augmented Generation)

To ensure the AI doesn't hallucinate or give fake legal advice, we use a hybrid AI approach. We combine a **Local AI Model (for searching)** with the **Gemini API (for reasoning and writing)**. 

### Why not just use Gemini for everything?
If we ask Gemini a legal question directly, it might guess the answer based on its general internet training. By using RAG, we first *search* our own verified legal documents locally, and then *force* Gemini to only read and explain the documents we found. This guarantees accurate, grounded advice with citations.

## 2. Component Breakdown: How Things Connect

### A. The Frontend (Next.js / React)
* **What it does:** It's the user interface running in the browser. 
* **How it connects:** It takes the user's email/password or chat messages and sends them to the backend using REST API calls (`fetch`). It attaches a secure JWT (JSON Web Token) to prove the user is logged in.

### B. The Database (MongoDB Atlas)
* **What it does:** Stores user accounts and their "Sessions".
* **How it connects:** The FastAPI backend uses the `motor` (async Python driver) to talk to MongoDB. 
* **Why it matters:** Instead of having many complex tables, we store a user's entire legal journey (their initial complaint, the legal chunks we found, the rights explanation, and the final RTI draft) in a single JSON document called a `session`.

### C. The Local Retrieval AI (`sentence-transformers` + `ChromaDB`)
* **What it does:** This is the "Local Model" part of the stack. It uses a lightweight local AI model called `all-MiniLM-L6-v2`.
* **How it connects:** 
  1. **Ingestion:** When you run the ingest script, this local model reads the exact text of the RTI Act and Rent Control Act, converts paragraphs into mathematical vectors (embeddings), and saves them in a local folder database called ChromaDB.
  2. **Searching:** When a user types *"My landlord didn't return my deposit"*, this local model converts that sentence into a vector, mathematically compares it to the database, and pulls out the exact section of the Rent Control Act dealing with deposits.
* **Why it matters:** Because this embedding and searching happens 100% locally on your machine, it is lightning-fast, highly private, and **costs absolutely zero Gemini API credits**.

### D. The Reasoning Engine (Google Gemini API)
* **What it does:** Understands context, explains dense legal text in plain English, and writes the formal RTI document.
* **How it connects:** Once ChromaDB finds the right laws locally, the FastAPI backend sends a prompt to Google's servers using your `GEMINI_API_KEY`.
* **The Magic Prompt:** The prompt looks something like this:
  > *"You are a legal explainer. The user said: 'My landlord didn't return my deposit.' Read ONLY these legal clauses we found: [Insert Local ChromaDB Results here]. Explain their rights in simple English and cite the exact section."*
* Gemini reads the injected laws, writes the explanation, and sends it back to the backend. We use `gemini-2.5-flash-lite` for simple multi-turn chat (because it's fast and cheap) and `gemini-2.5-flash` for the complex document writing.

### E. The PDF Generator (ReportLab)
* **What it does:** Takes the plain text generated by Gemini and makes it look like an official government document.
* **How it connects:** Once Gemini generates the "Information Requested" clauses, the FastAPI backend uses the `reportlab` Python library to stamp it onto a formal RTI template (with the correct TO and FROM addresses), turning it into a downloadable PDF that is passed back to the Next.js frontend.

---

## 3. The Full Step-by-Step Data Flow

1. **User Login:** User enters credentials in Next.js $\rightarrow$ FastAPI checks MongoDB $\rightarrow$ FastAPI returns a JWT token.
2. **Intake:** User types "Garbage isn't collected" in Next.js $\rightarrow$ FastAPI sends this to Gemini (Flash-Lite) to extract the core facts into a structured JSON object.
3. **Retrieval:** FastAPI takes the extracted facts $\rightarrow$ passes them to the local `sentence-transformers` model $\rightarrow$ ChromaDB returns the municipal grievance laws.
4. **Explanation:** FastAPI sends the municipal laws + user facts to Gemini (Flash) $\rightarrow$ Gemini explains the rights and suggests an RTI $\rightarrow$ FastAPI saves this to MongoDB and sends it to Next.js.
5. **Drafting:** User clicks "Draft RTI" $\rightarrow$ FastAPI asks Gemini to write the RTI clauses based on the facts $\rightarrow$ ReportLab turns it into a PDF $\rightarrow$ Next.js downloads it to the user's computer.
